# Architecture

## Overview

A front-end-first Next.js App Router site. No admin dashboard, no custom CRM/CMS, no payments, no live OPERON/TAYA integration in Batch 001.

```
Browser
  │
  ├── Server Components (default) ── lib/content/* (typed content)
  │
  ├── Client Components (interactive only)
  │     ├── SiteHeader (mobile nav)
  │     ├── Reveal (IntersectionObserver)
  │     ├── InquiryForm / SchoolInquiryForm  ── POST ──► app/api/*
  │     └── AthleteRegistrationForm (submission disabled)
  │
  └── API Routes (Node runtime)
        ├── /api/inquiry          → Zod → rate limit → Resend
        └── /api/school-inquiry   → Zod → rate limit → Resend
```

## Rendering strategy

- Static generation for all public pages (39 pages in the build).
- Waiver detail pages use `generateStaticParams` over the 13 documents.
- API routes are dynamic, Node runtime (Resend SDK).

## Content layer

All copy lives in `lib/content/` as typed objects:

- `site.ts` — identity, contact placeholders, navigation, stats.
- `programs.ts` — 8 training disciplines, 6 engagement formats, principles.
- `bio.ts` — verified founder bio, education, certifications, accomplishments, `pendingVerification`.
- `technology.ts` — Output Sports, Valor, VertiMax, Vertec with verification notes.
- `waivers.ts` — 13 draft waiver documents with sections and review notes.

This separation is the seam for a future TAYA mapping (see `taya-content-contract.md`). Presentation components read from these modules and never hardcode copy that should be editable.

## Validation

`lib/validation.ts` holds Zod schemas shared by client forms and server routes, so the same rules apply on both sides. `fieldErrors()` flattens a `ZodError` into a field→message map for accessible rendering; `ageFromDate()` computes age for the minor/guardian boundary.

## Forms and data classes

- **Class A — public inquiry** (contact, training, school, partner): live. Server-side validation, honeypot, size cap, in-memory rate limit, Resend delivery. No medical data accepted.
- **Class B — sensitive registration/waivers**: complete front end, submission disabled. Requires approved secure storage, guardian consent, signature audit, versioned acceptance, retention/deletion, RBAC, secure delivery, privacy review.

## Security headers

`next.config.ts` sets CSP, HSTS, X-Frame-Options, Permissions-Policy, Referrer-Policy, and nosniff on all routes. `poweredByHeader` is off. See `privacy-security-plan.md`.

## SEO

`lib/seo.tsx` provides `pageMetadata()`, `organizationSchema` (SportsActivityLocation with region/country only — no invented street address or phone), `breadcrumbSchema`, and `JsonLd`. Sitemap and robots are generated by `app/sitemap.ts` and `app/robots.ts`.

## Styling

Tailwind with brand tokens in `tailwind.config.ts`; base and component classes in `app/globals.css` (`.shell`, `.display-xl`, `.btn-primary`, `.field-input`, `.card`, etc.). Motion respects `prefers-reduced-motion`.
